# 固定 3DGS 模型的多视角深度修正

## 1. 研究问题

遮挡边缘处，前景和背景都可能参与 3DGS 的像素合成，期望深度会落在两个表面之间。第一版根据射线上的深度分布筛掉可疑点。这次检验能否把其中一些点放回合理的表面，同时控制误修。

以加权中值为主要对照。三种修正策略使用同样的候选，也在同一批有效像素上进行比较。实验固定已有 3DGS 参数，用 NumPy 在 CPU 上完成投影、选层和验证。

## 2. 方法与实现

1. **计算实际贡献。** 将三维高斯投影为屏幕椭圆。对每个像素，从近到远计算 \(w_i=\alpha_i\prod_{j<i}(1-\alpha_j)\)，其中 \(\alpha_i\) 是高斯在该像素的有效不透明度。用 \(p_i=w_i/\sum_jw_j\) 作为归一化权重。加权中值是累积 \(p_i\) 首次达到 0.5 的深度。
2. **提出前后层。** 检查排序后相邻深度的间隙。要求间隙至少为 0.012 个归一化模型单位，且间隙前后的贡献质量均至少占 10%。选择满足条件的最大间隙，在每组内各重新求一次加权中值。每个待检查像素最多有两个替代候选。
3. **验证几何。** 用相机内参把某个候选深度反投影到三维空间，再投到四个邻近视角。令 \(r=z_{\text{候选投影}}-z_{\text{辅助表面}}\)。当 \(|r|\leq 0.012\) 时，辅助表面支持候选；\(r<-0.012\) 时，候选落在可见表面的前方，记录自由空间冲突；\(r>0.012\) 时，表面可能挡住候选，该视角不提供支持也不计冲突。几何证据只从达到不透明度和深度跨度门槛的辅助像素读取。
4. **核对图像。** 将目标像素周围 3×3 的亮度小块按候选深度反投影，并在辅助图中双线性采样。小块内采用局部等深近似。对纹理充足的图块计算零均值归一化互相关，转换为 \(c=(1-\mathrm{ZNCC})/2\)。候选需要在同一视角满足 \(c\leq 0.25\)，且比中值候选至少降低 0.06，才获得一票光度支持。
5. **决定是否替换。** 联合版要求至少两个辅助视角各自同时通过几何与光度检查，且所有可靠几何视角都没有发现自由空间冲突。其余像素沿用中值。几何单项与光度单项分别用于检验两种证据各自的贡献。完整阈值、判定顺序和并列规则见 [预先确定的实验协议](REFINEMENT_PROTOCOL.md)。

几何和光度筛选使用缓存的模型输出、相机和配套 RGB。评估视角的参考深度在选值结束后才读取。遮挡几何的判断借鉴已有多视角深度融合方法，本项目检验其在固定模型候选深度选择中的取舍。[多视角可见性深度融合](https://mordohai.github.io/public/Merrell_DepthMapFusion07.pdf) · [GVGS](https://arxiv.org/abs/2601.20331)

## 3. 逐项验证

| 验证步骤 | 怎么检查 | 观察结果 |
| --- | --- | --- |
| 射线分层 | 用两层已知权重和独立的逐射线实现对照，另外检查质量过小的假层 | 向量化结果与独立实现一致，原版期望深度在打开候选输出后保持逐元素一致 |
| 旧版回归 | 重新运行第一版的六组合成实验，比较指标 CSV 的 SHA-256 | 新旧指标文件逐字节一致 |
| 坐标投影 | 对旋转相机做「像素和深度 → 三维点 → 像素和深度」往返 | 恢复原像素中心和相机 Z |
| 遮挡与匹配 | 分别构造前方冲突、同一表面、被挡和越界四种情况，并测试双线性插值及平坦图块 | 几何状态符合预期，平坦图块不给光度票 |
| 联合逻辑 | 构造两类证据分属不同视角、两项都通过、其余视角存在冲突三种情况 | 只有同一视角内的双证据满足票数且无冲突才修改 |
| 公开数据对齐 | 椅子和警示牌各用三个校准视角检查轮廓和深度约定 | 椅子轮廓 IoU 为 0.868–0.907，警示牌为 0.910–0.920。两组数据的参考点云重投影中，相机 Z 与参考深度的中位绝对差均低于沿射线距离 |
| 评估一致性 | 对每个视角、每个阈值检查误差计数 | 大误差点数等于「中值大误差点数 − 修好数 + 改坏数」，所有方法使用同一有效集合 |

## 4. 结果

椅子开发组包含早期尝试用过的八个视角，开发结果独立保留。下表仅汇报此前未用于尝试的椅子八视角和第二物体警示牌八视角。两组采用同一套规则，分辨率均为 128×128。这里的「保留视角」指修正方法的评价划分，公开 3DGS 模型的原始训练视角由发布者确定。参考深度来自源网格渲染。

大误差阈值为 0.05 个数据集场景单位。MAE 和大误差率对视角等权；改动、修好和改坏是像素计数。椅子含 30,366 个共同有效像素，警示牌含 28,931 个。

| 椅子 | 加权中值 | 0.04596 | 19.42% | — | — | — |
| 椅子 | 几何单项 | **0.04488** | **19.27%** | 131 | 58 | 14 |

| 警示牌 | 期望深度 | 0.04975 | 10.71% | — | — | — |

几何单项在两个物体上的总体误差最低。联合规则的改动更少，在椅子上改坏了 1/23，在警示牌上改坏了 1/11。几何单项分别改坏 14/131 和 4/44，警示牌的两种误修比例相同。把大误差阈值改成 0.025 或 0.10，两个物体仍由几何单项取得最低大误差率。结论是描述性的，反映相同阈值下的修正收益和误修代价。

## 5. 逐像素复盘

### 修对的案例

椅子开发组视角 14，像素 \((x,y)=(90,66)\)。默认中值为 **3.5268**，前层候选为 **3.5230**，后层候选为 **3.8742**。下表列出后层候选和中值的真实运行记录，数值取自该组的 `example_trace.npz`。

| 辅助视角 | 后层几何状态 | 中值光度代价 | 后层光度代价 | 联合投票 |
| --- | --- | ---: | ---: | --- |
| 6 | 支持 | 0.5465 | 0.2110 | 支持 |
| 22 | 支持 | 0.0584 | 0.1106 | 光度改善不足 |
| 27 | 可能被遮挡 | 0.5229 | 0.8846 | 不计入 |
| 9 | 支持 | 0.8880 | 0.1959 | 支持 |

视角 6 和 9 同时通过两项检查，程序选择 3.8742。随后才与参考深度 **3.8517** 比较。误差由 **0.3248** 降至 **0.0225**，因此计为修好一点。

### 改坏的案例

警示牌保留组视角 120，像素 \((x,y)=(64,64)\)。参考深度为 **4.5227**，默认中值为 **4.4759**，原误差 **0.0468** 在 0.05 阈值以内。升版规则把深度替换成前层候选 **3.3269**，误差升到 **1.1958**。相机 107 和 128 都给出了前层的几何支持，且前层的光度代价分别从 **0.8865 降到 0.0294**、从 **0.5489 降到 0.0407**。按当前规则，两票足以触发修改。

这条记录展示了误修如何发生：同一个高斯模型的辅助深度支持了较近的候选，两个局部图块也出现了更好的匹配，但这一候选与参考表面相差约 1.196 个场景单位。跨视角共享的模型可能出现一致偏差，局部纹理也可能给出歧义。对高风险的长距离改动，后续可以检验更严格的改动上限或更大的核对图块。该案例只用于事后分析，汇总表仍使用协议里的固定规则。[警示牌误修记录](../evidence/sign_heldout/false_edit_view_120.json) · [椅子误修记录](../evidence/chair_heldout/false_edit_view_120.json)

## 6. 候选覆盖与结论边界

椅子中值的 5,940 个大误差点里，631 个有可用替代候选，占 10.62%。警示牌的 2,684 个里有 131 个，占 4.88%。这是用参考深度事后计算的候选上限诊断。它把当前限制拆成了两部分：分层规则覆盖的坏点有限，联合投票在覆盖到的区域内也只改了一小部分。两个数据集的候选筛选分别只触及 1,528 和 302 个像素。

因此，这组证据支持的结论是：**在固定 3DGS 模型上，可见性几何能修正部分中值错误。加入严格的光度门槛会减少改动，整体收益也随之缩小。** 受限于两个由网格合成的对象，同物体的多视角不宜作为独立样本做泛化或显著性判断。

## 7. 复现与结果文件

在项目目录使用已有的 Python 环境。数据下载、评估和测试命令如下。

~~~powershell
python -m unittest discover -s tests -v
python -m gsdepth.tools.fetch_chair
python -m gsdepth.tools.fetch_chair --object sign
python -m gsdepth.benchmarks.run_refinement --object chair --split development
python -m gsdepth.benchmarks.run_refinement --object chair
python -m gsdepth.benchmarks.run_refinement --object sign
~~~

各组的 `metrics.csv` 保存逐视角和阈值结果，`summary.json` 保存汇总、实际相机编号、阈值、对齐检查和源文件 SHA-256。`example_trace.npz` 保存一个实际演示帧的逐候选深度、证据状态和光度代价。`median.ply` 与 `joint.ply` 使用相同像素导出。
